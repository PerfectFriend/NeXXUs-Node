# ADR-0011: Wire Protocol v4 — транспортная аутентификация и честные доказательства

**Статус:** ПРЕДЛОЖЕН (требует решения владельца)
**Дата:** 2026-11-22
**Закрывает находки аудита rc3:** H-4 (handshake без Noise), H-5 (PoR prover выбирает сам), H-6 (Merkle без domain separation), H-7 (SMP sender из payload, спуфинг)

## Мотивация

Wire v3 (ADR-0001) гоняет AEAD-кадры поверх голого TCP, но handshake — это обмен долгосрочными pubkey в открытом виде без доказательства владения приватным ключом и без forward secrecy. PoR «доказательство» — это SHA256-формула, которую prover может посчитать сам, не имея данных. SMP-envelope несёт `sender` в payload вне AEAD. Все четыре — про то, что peer доказуемо не доказывает.

## Решение: wire v4

### 1. Транспорт: Noise XX + prologue (закрывает H-4)

- Handshake по **Noise_XX_25519_AESGCM_SHA256** (или ChaCha20Poly1305 — решить по бенчам; AESGCM быстрее с AES-NI).
- Prologue = hash(wire_version ‖ node_id_self ‖ node_id_peer_expected ‖ bootstrap_epoch) — биндит сессию к обеим идентичностям и эпохе, защищает от replay/relay между узлами.
- После handshake — эфемерные ключи сессии; долгосрочный ключ tylko для подписи handshake-trascript (identity key подписывает transcript hash,Noise XX уже даёт mutual auth по статическим ключам).
- Forward secrecy: эфемерный ключ уничтожается после закрытия соединения (Zeroizing).
- Compatibility: v4-узел слушает на новом порту (или ALPN-like négociación по первому байту версии); v3 остаётся на старом до конца deprecation window (2 релиза), потом отключается фиче-флагом.

### 2. PoR от верификатора (закрывает H-5, H-6)

- **Domain separation:** все Merkle-хеши считаются как `SHA256("nexxus-por-v4" ‖ node_id ‖ chunk_hash ‖ index ‖ ...)` — отдельный префикс для PoR, отдельный для обычных chunk-хешей. Старые деревья несовместимы (версия в корне дерева).
- **Challenge:** верификатор (auditor) присылает `challenge = H(node_id ‖ chunk_hash ‖ epoch ‖ nonce_verifier)`; prover доказывает включение по этому challenge, подписывает доказательство **сессионным ключом** (а не долгосрочным), иначе replay.
- SNARK (Groth16) остаётся roadmap Phase 3 — до него PoR = Merkle inclusion proof + challenge, это уже нельзя подделать без данных.

### 3. SMP: sender внутри AEAD (закрывает H-7)

- Envelope v4: `AEAD(key_session, aad = "nexxus-smp-v4" ‖ recipient ‖ nonce, plaintext = sender ‖ payload ‖ expiry)` — sender в plaintext, но аутентифицирован, подменить нельзя.
- Replay: `nonce` — монотонный счётчик отправителя + окно приёма 2^16 (уже есть в SMP), плюс привязка к сессии.

## Mig strategy

1. v4 behind cargo feature `wire-v4` (default on в rc4), v3 fallback до v0.231.
2. Golden vectors: handshake transcript, PoR challenge/response, SMP envelope — в `tests/golden/` (уже есть `scripts/generate-golden-vectors.ts` для v3).
3. e2e: 2 ноды, mixed v3/v4 — должны договориться; v4-only — должны отказать v3 после deprecation.

## Риски

- Noise handshake добавляет 3 RTT (XX) — можно XX→IK если bootstrap-пин даёт нам pubkey peer заранее (IK = 2 RTT... 1 RTT). Рекомендую IK с fallback на XX.
- Миграция существующих peer-записей: node_id не меняется, только транспорт.

## Открытые вопросы владельцу

1. Noise pattern: XX (3 RTT, проще) vs IK (нужен bootstrap-пин pubkey, 1 RTT)?
2. Deprecation window для v3: 2 релиза или до первого mainnet?
3. PoR: challenge от аудитора только, или peer-to-peer challenge тоже (для self-check)?

## Deprecation v3 (реализовано 2026-11-26, ae45e7b+)

- Mixed-mode: основной порт sniff'ит первые 4 байта; `NXV4` → v4, иначе v3. `NEXXUS_P2P_V4_SNIFF=0` отключает sniff.
- Deprecation v3: метрика `v3_conns` в `node_metrics`, rate-limited warn `conn.v3.deprecated` (раз в 300с).
- Жёсткое отключение v3: `NEXXUS_P2P_V3_ALLOW=0` — соединения без magic `NXV4` дропаются сразу (`conn.v3.rejected`).
- Deprecation window: 2 релиза после mixed-mode, затем v3 отключается по умолчанию (ADR update).
